How your notes stay private

What is encrypted, who holds which key, what the storage provider can see, and what is not protected.

Status and limits

  • Sempere is free software under the GPL-3.0-or-later and comes with no warranty.
  • The design and code have not been independently audited.
  • Only your key opens your notes. If every copy is lost, nobody can recover them. Save the recovery kit and keep backups.
  • Report vulnerabilities privately through GitHub; see SECURITY.md.

The short version

Sempere keeps your notes in a vault: a plain folder of encrypted files. You make the keys, on your own devices. Every file is encrypted to those keys before it is saved, so whoever stores the folder (iCloud Drive, a NAS, a backup disk) holds ciphertext they cannot read. There is no server of ours.

The pieces

Device keys

A key is one line of text, an age identity that you generate on the device. It stays in the Keychain, optionally behind Face ID or Touch ID. You can export it, import it on another device, or print a paper recovery kit (the key as a QR code and as text, with steps that need only stock tools). Keys are hybrid post-quantum, ML-KEM-768 with X25519: an attacker must break both, which covers copies of your files kept for later ("harvest now, decrypt later").

The vault and its recipients

The vault lists the public keys it is encrypted to (its recipients), and holds a random vault secret, itself encrypted to those keys. The device list is authenticated, so someone with write access to your storage cannot quietly add their own key: the app notices and asks. When a key is removed the secret rotates, and the new secret is linked to the old one by two signatures, Ed25519 and ML-DSA-65, which both have to verify.

Encrypted notes

A note is a folder of write-once revision files, each an age file. Saves are appended, never overwritten, so sync tools never see a conflict and two devices can edit the same note and merge. Each file carries an authentication tag under the vault secret, so a file that someone planted or changed is rejected, not decrypted and trusted.

Encrypted attachments

Images, PDFs, video, recordings and transcripts are separate encrypted files, named with a keyed hash (no plaintext hashes on storage) and padded to a size class so exact sizes are not given away.

No server

Sync is whatever moves the folder: iCloud Drive or another folder the Files app reaches; the CLI can also mirror to a WebDAV share. The app has no analytics and no network code of its own.

What anyone holding your files can see

Encryption keeps what you wrote, drew, recorded and attached private. It does not keep the existence of the vault private. Whoever stores the folder can see:

  • file and folder names (random UUIDs, not titles) and how many notes there are;
  • the size of each file (attachments are padded to a size class, revisions are not) and, for attachments, their kind (image, PDF, audio, and so on);
  • when files were created and changed, which shows when you write and sync;
  • the public keys and labels in vault.json (the labels you gave your devices).

Note titles, notebooks, tags and text are inside the encrypted files.

What is not protected

Limits, from DESIGN.md, the format specification and the project's security review.

  • An unlocked device. If someone can use your unlocked iPad or Mac, or malware runs there, they can read what you can read. Threats that need the unlocked device or your key file are out of scope.
  • A lost key. If every copy of your key is gone, nobody, including the developer, can decrypt your notes. Keep the paper kit and a backup.
  • Removing a device does not unsee. A removed device keeps whatever it already decrypted and copied. Removal rotates the secret and re-encrypts for the future.
  • Metadata. The sizes, times and file kinds above, and the number of notes, are visible to your storage provider.
  • Quick voice notes. Recording from the Lock Screen is sealed without your key, so anyone holding the locked device (after its first unlock) could add a voice note to your inbox. They cannot read your notes.
  • Some format fields are not authenticated. The vault's format and features markers can be changed by someone with write access to your storage. The review found no data loss from this.
  • The web viewer is as trustworthy as the host that serves it. It decrypts in your browser and sends your key nowhere, but whoever controls the server can change the page. Serve it from a host you control, and use a browser profile without extensions for sensitive vaults. The demo here is a sample vault with a public key.
  • On-device recognition and transcription use Apple's frameworks. Handwriting search and recording transcripts run on your device and are stored inside the encrypted note, but you are trusting Apple's code to do that work.
  • No outside audit yet. The project had its own security review in October 2026 and fixed what it found; the repository records no independent third-party audit.

Check it yourself

  • The on-disk format is public: docs/format.md. Notes are standard age files, so age -d, gunzip and jq recover a note without Sempere at all.
  • The age implementation is checked against the public C2SP test vectors and against the reference age tool.
  • Why post-quantum, and the exact construction: docs/post-quantum.md.
  • Found a vulnerability? Please report it privately: SECURITY.md.
