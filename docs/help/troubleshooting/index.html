Troubleshooting

Sync that looks stuck, missing notes, joining that stalls, a lost kit, large vaults, and the messages you might see.

Sync looks stuck

The bar under the note list appears only when something is wrong. While Sempere is syncing, synced, offline or waiting for iCloud, there is no bar; Sync Targets… (in the sidebar’s More menu, or File ▸ Sync Targets… on the Mac) shows each target’s state, and Sync Now syncs at once.

  • “Offline. Changes are kept on this device and sync when the server can be reached.” (in Sync Targets…) Your changes are safe; they sync later.
  • “The folder cannot be reached now.” A share or drive is not connected. Sync Now reconnects a share.
  • “n changes not synced yet” that does not go down: check the server’s address, password (Server Settings…) and certificate, or that the folder is still there.
  • “n changes waiting for iCloud to upload”: Sempere has written them to the iCloud Drive folder; iCloud has not sent them yet. Check that the device is online, signed in, has iCloud Drive on, is not in Low Power Mode and has free iCloud storage. The status says Synced again once iCloud has taken everything, and an upload error shows only after about ten minutes of trying.
  • “Changes from other devices arrive when the vault is unlocked”: a closed or locked vault only uploads. Open and unlock it.
  • “The folder is gone or can no longer be opened” (also the bar): the target folder was moved or deleted, or its permission lapsed. Choose Again… in Sync Targets, or remove the target.
  • “The server refused the user name or password” or “The server’s certificate is not trusted or changed” (also the bar): fix it in Server Settings….
  • “The vault’s device list was changed both on this device and on the server.” (also the bar) Both copies were kept and notes still sync; the device that manages devices settles it with its next sync.
  • A target that could not be reached for a week while the device was online also shows in the bar.

iCloud holds the sync folder as a package

Sync Targets… warns “iCloud Drive syncs this folder as one package, so changes made on two devices at once can hide each other’s files.” under a folder target. On some iCloud accounts, a folder whose name ends in .sempere is kept as a single item, not as a folder of files. Then changes from two devices can collide as whole-vault versions, deleted notes can come back, and sync is slow. Your notes on each device are safe, because they live in the app.

Since 1.3, a new folder target is named <vault>.sempere-vault (the vaults kept inside the app stay .sempere), a name that is declared a plain folder. Existing .sempere targets keep working. Update every device of a vault to 1.3 before you add a .sempere-vault folder on any of them; older versions do not know the name and would sync a second copy beside it.

To move to a plain folder, tap How to Fix… on the warning. It shows these steps:

  1. Pause Sempere on every device: leave it closed until step 3. Skip steps 1 to 3 if the warning says the folder has no conflicting versions to merge back.
  2. On a Mac, merge back what the conflicting versions hold with the command line: sempere vault conflicts shows what is there, sempere vault conflicts --merge --dry-run shows the plan, and sempere vault conflicts --merge does it. The command needs the CLI to be a device of the vault (Keys and devices). It copies back files only a conflict version holds, each checked under the vault’s key and never overwriting anything; a file that fails goes to a quarantine folder (by default under ~/.local/state/sempere/conflicts/). It changes nothing else, and clears the Finder’s package flag when everything is merged.
  3. Open Sempere on that Mac only, and let it sync once with the old folder, so the recovered files reach its copy.
  4. On one device, Add Folder… and pick a folder in iCloud Drive that does not hold the old one (a new folder is simplest). Sempere makes <vault>.sempere-vault in it and copies the vault in.
  5. On each other device, add the same folder, then remove the old target.
  6. Before you move the old folder to the Trash, check that the files the merge copied back are in the new folder, and keep the merge’s quarantine folder.

Renaming the old folder does not help: iCloud Drive keeps it a package.

A deleted note came back, or went away

A deletion is an edit like any other; the latest change decides. To see which device’s change decided it, run sempere notes revisions "Title" on each device’s copy of the vault. It lists every revision of the note with its ops and device, the revisions that do not read on that machine and why, and which revision set the deleted flag. See the CLI.

A note is missing on my other device

  1. Is it the same vault? Two vaults can have the same name.
  2. Do both devices share a target? Devices only see each other’s changes through a sync target they both use. Sync Targets… ▸ Details and Repair lists the devices whose notes each target held at the last sync.
  3. Has it arrived? The writing device must have synced (look at its bar), and the other one too.
  4. Is it in Recently Deleted? A deletion on any device applies everywhere.
  5. Is a filter on? Select All Notes in the sidebar and clear the search field.

Joining a device stalls

  • The home device never shows the request: both devices must sync with the same target. Sync Now on both.
  • The new device never sees the approval: keep its join screen open and tap Check Now; make sure it syncs with the same target as the home device.
  • “The request to join expired”: requests are deleted after 7 days. Ask to Join again.
  • The words do not match: check them again on the other device. If they still do not match, stop: the device may have been given a different copy of the vault.

See Add a second device.

The vault does not open

  • The unlock screen offers Join and Take Over instead of unlocking: this device has no key for the vault. Join it, or take over with the recovery kit.
  • “Forget This Device’s Key…” on the unlock screen: this device’s key for the vault can no longer be read (for example after Face ID was set up again). Forget it, then join again or take over.
  • The recovery key is refused: check that you typed the whole AGE-SECRET-KEY-PQ-1… key (each line’s checksum catches typos), and that the kit belongs to this vault. A kit that was replaced no longer opens the vault for new changes.

“This device is not on the vault’s newest device list”

The device that manages devices removed this one, or a takeover left it out. It writes and syncs nothing more. Save what it has not synced (Save Files…, or export the notes), then remove the vault from it. If the removal was a mistake, a takeover with the recovery kit that keeps this device undoes it. See Managing devices and keys.

“This vault’s device list was changed without its key”

Someone who can change the vault’s storage (a sync service, a shared folder) edited its list of devices without the vault’s key, or put back an older one. Your notes can still be read; nothing is written to the vault until the list is fixed. If a sync service or another device is at fault, the next sync from the device that manages devices puts the list back. Otherwise take over with the recovery kit.

Lost the recovery kit

  • The device that manages devices still works: Settings ▸ Sync & Devices ▸ Devices ▸ Replace Recovery Kit…, and print the new kit.
  • Someone else may have it: use Re-encrypt Everything… instead, so nothing on your storage opens with it any more. Watch for takeover alerts: a takeover you did not make means someone used it.

If no device opens the vault any more and you have no kit and no passphrase copy, the notes cannot be recovered. That is the price of nobody else holding your keys.

Large vaults are slow

  • The first sync on a new device downloads everything; let it finish on Wi-Fi.
  • Big PDFs open faster as their own notes. See Big notes, big PDFs, big vaults.
  • Settings ▸ Backups & History ▸ Storage: clear caches if space is short, and remove unused attachments.

Handwriting search misses words

See Search: when a word is not found.

Reporting a problem

Open an issue at github.com/anthonytw/sempere/issues. Describe what you did and what happened; never paste a real key or real notes. For crash reports, see Support.
